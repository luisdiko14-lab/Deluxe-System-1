Engineering Architecture Decision

Why live-build Over Cubic?

While Cubic relies on manual GUI chroot interactions that drift over time, Debian/Ubuntu's live-build (lb config / lb build) defines the entire operating system declaratively as version-controlled text files. Running sudo ./build.sh on any clean Ubuntu 24.04 host or GitHub Actions runner produces an identical, auditable, idempotent deluxe-system-1-1.0-amd64.iso and SHA256 checksum every single time.

✓ live-build 100% Scriptable, Git-friendly, Idempotent CI/CD
✕ Cubic GUI Manual clicks, opaque state, hard to reproduce

Verify both UEFI (OVMF) and Legacy BIOS boot paths in QEMU/KVM before flashing physical hardware:

                        
# 1. Test UEFI Mode (requires ovmf package)
qemu-system-x86_64 -enable-kvm -m 4096 -smp 4 \
  -bios /usr/share/ovmf/OVMF.fd \
  -cdrom build/deluxe-system-1-1.0-amd64.iso -vga virtio

# 2. Test Legacy BIOS Mode
qemu-system-x86_64 -enable-kvm -m 4096 -smp 4 \
  -cdrom build/deluxe-system-1-1.0-amd64.iso -vga virtio

                    Engineering Runbook
                    
Top 5 live-build Troubleshooting Fixes


                    

                        

                            
                                1. `E: Unable to locate package` during `lb build` chroot stage
                                
                            
                            

                                Ensure --archive-areas "main restricted universe multiverse" is passed to lb config, and third-party GPG keys (Mozilla, Microsoft VS Code, Docker) are placed in config/archives/*.key.chroot.
                            

                        


                        

                            
                                2. ISO exceeds 4.7 GB DVD/FAT32 single-file ceiling
                                
                            
                            

                                Use XZ high-ratio SquashFS compression (MKSQUASHFS_OPTIONS="-comp xz -b 1M -Xdict-size 100%") and strip /var/cache/apt/archives/* plus /usr/share/doc/* in the final chroot cleanup hook.
                            

                        


                        

                            
                                3. `chroot: failed to run command '/bin/sh': Exec format error` or mount busy
                                
                            
                            

                                A previous interrupted build left chroot/proc or chroot/sys mounted. Our idempotent build.sh safely unmounts stale pseudo-filesystems and runs lb clean --purge before rebuilding.
                            

                        


                        

                            
                                4. UEFI Secure Boot or Hybrid ISO fails to boot on older BIOS PCs
                                
                            
                            

                                Install xorriso, isolinux, syslinux-efi, and grub-efi-amd64-bin on the build host, and pass --bootloaders "syslinux,grub-efi" to lb config.
                            

                        


                        

                            
                                5. Snap daemon re-installs itself when installing `firefox`
                                
                            
                            

                                Ubuntu's transitional firefox package pulls snapd. Pin Package: snapd / Pin-Priority: -10 in /etc/apt/preferences.d/nosnap.pref and prioritize packages.mozilla.org with priority 1001.
